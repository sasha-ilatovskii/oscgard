gladshmr User Guide

gladshmr is an iPad app for building a virtual monome-style control surface. You can place grid-like and arc-like devices on a shared canvas, play them directly with touch, receive LED state from other software, and send control events over Network OSC or through a BLE Bridge.

Supported virtual devices:

  • Grid: 8x8, 16x8, and 16x16
  • Arc: 2 or 4 encoders

Quick Start

  1. Open the side panel by dragging or tapping the handle on the left edge.
  2. Tap the pencil button to enter edit mode.
  3. Use the plus button to add a Grid or Arc.
  4. Tap the wrench-and-screwdriver button on a device to open its settings.
  5. Choose Network or BLE Bridge as the transport.
  6. Leave edit mode to play the devices.

On a fresh install, gladshmr starts with one 4-encoder Arc and one 16x8 Grid. Your layout, connections, and visual settings are saved automatically.

Layout and Devices

The main screen is a canvas made of layout cells. The default canvas is 4 columns by 3 rows. Open Grid Settings from the side panel to change the canvas size from 1 to 8 columns and 1 to 8 rows.

In edit mode, you can move devices, resize them, open device settings with the wrench-and-screwdriver button, or delete them with the trash button. If you shrink the canvas, devices are clamped to fit where possible; devices that cannot fit may be removed from the saved layout.

Use Add Device to create:

  • Arc with 2 or 4 encoders
  • Grid in 8x8, 16x8, or 16x16 edition

Device names are generated automatically and must be unique. The device name is also its OSC prefix, so renaming a device changes the OSC addresses it uses.

Device Settings

In edit mode, tap the wrench-and-screwdriver button on a device to open its settings panel.

The top field is the device name. The OSC prefix is shown below it. For example, a device named STG1681 uses addresses such as /STG1681/grid/key.

The status row shows whether the device is ready, connected, waiting for Bluetooth, or missing permission. Settings differ slightly by transport and device type.

Transport

Network uses OSC over Wi-Fi or LAN. The device listens on its incoming port and can connect to another OSC target for outgoing touch and encoder events.

BLE Bridge sends events through a connected bridge and maps the virtual device to a bridge slot.

Arc Settings

Arc devices include two extra settings:

  • Arc Layout: number of encoders per row. A 2-encoder Arc supports 1 or 2 per row; a 4-encoder Arc supports 1, 2, or 4 per row.
  • Encoder Input: Ring mode tracks circular dragging around the ring; Wheel mode shows a circular wheel control for stepped encoder movement.

Appearance

Each Grid and Arc can use one of two looks:

  • Realistic: default hardware-style rendering
  • VFD: blue-green phosphor display style

Open Shader Controls to tune the look. Reset restores the visual defaults for the current device while keeping the selected look.

Network OSC

Each device owns its own OSC server and Bonjour service. gladshmr publishes OSC services using _osc._udp, so compatible apps on the same network can discover the virtual devices automatically.

Default incoming ports:

  • Grid starts at 8000
  • Arc starts at 8001
  • Additional devices use the next free port

In Network mode, the connection list shows discovered OSC services. Tap a service to resolve and connect to it. If discovery is not available, choose Enter Host Manually and enter the target host and UDP port.

The Incoming Port setting controls the local UDP port where that virtual device receives OSC messages. When the port changes, gladshmr restarts the local socket and republishes the Bonjour service.

Outgoing Network connections are saved per device and restored when the app launches again.

Playing Grid

Touching a Grid sends key events. Coordinates use x for column and y for row, with origin at the top-left.

Outgoing Network event: 


/<device>/grid/key x y s

Where s is 1 for press and 0 for release.

Grid supports multi-touch. When a finger moves from one cell to another, gladshmr sends a release for the previous cell and a press for the new cell.

Grid LED Messages

gladshmr receives the following Grid LED messages: 


/<device>/grid/led/set x y s
/<device>/grid/led/all s
/<device>/grid/led/map x_off y_off rows[8]
/<device>/grid/led/level/set x y l
/<device>/grid/led/level/all l
/<device>/grid/led/level/map x_off y_off levels[64]
/<device>/grid/led/level/row x_off y levels...
/<device>/grid/led/level/col x y_off levels...
/<device>/grid/led/state hex_string

Binary LED messages use 0 or non-zero values. Level messages use brightness levels from 0 to 15.

The state message expects one hex character per Grid cell. 0 is off and f is full brightness. The string length must match rows * cols.

Two legacy/debug helper messages are also supported: 


/cell x y brightness
/clear

/cell uses a floating-point brightness from 0.0 to 1.0.

Playing Arc

Arc devices send encoder and key events.

In Ring input mode, drag around a ring to send encoder delta. In Wheel input mode, use the circular wheel control in the center of the encoder. The small button near each ring sends key down/up.

Outgoing Network events: 


/<device>/enc/delta ring steps
/<device>/enc/key ring state

ring is zero-based. state is 1 for press and 0 for release.

Arc LED Messages

gladshmr receives the following Arc ring LED messages: 


/<device>/ring/set ring led level
/<device>/ring/all ring level
/<device>/ring/map ring levels[64]
/<device>/ring/range ring start end level
/<device>/ring/state strings...

Arc LED levels use 0 to 15. Ring LEDs are addressed from 0 to 63.

For /ring/state, send one 64-character hex string per ring. Each character represents one LED brightness level.

Tilt and Sensors

Grid devices support tilt sensor requests.

Enable or disable a sensor with: 


/<device>/tilt/set sensor state

Sensors:

  • 0: gravity/accelerometer-derived values
  • 1: gyroscope rotation-rate-derived values

When enabled, gladshmr captures a baseline and sends: 


/<device>/tilt sensor x y z

x, y, and z are normalized to 0...255, centered around the captured baseline.

BLE Bridge

Use BLE Bridge mode when you want the virtual device to communicate through compatible bridge hardware instead of direct Network OSC.

In a device settings panel:

  1. Set Transport to BLE Bridge.
  2. Tap refresh in the BLE Bridge section if no bridge appears.
  3. Tap a discovered bridge to connect.
  4. Assign the device to Slot 0 or Slot 1.

Only two bridge slots are currently supported. Assigning a slot to one device clears that slot from any other device, so each slot maps to at most one virtual device.

The bridge configuration is sent automatically after layout or slot changes. Config writes are debounced briefly so rapid edits do not spam the bridge. gladshmr also remembers the last bridge and tries to reconnect when Bluetooth becomes available.

If Bluetooth is off or permission is missing, the status row and BLE Bridge section show that state.

Appearance and Shader Controls

Shader Controls are live visual controls for each device. Settings are saved per device name.

The LED gradient toggle is a temporary preview. It fills the device with a brightness gradient so you can judge the material and color settings. The preview turns off automatically when the sheet closes.

Troubleshooting

No OSC devices are found

  • Make sure both apps are on the same Wi-Fi or LAN.
  • Allow Local Network permission for gladshmr in iPadOS settings.
  • Check that the target app publishes _osc._udp.
  • Try Enter Host Manually with the target IP address and port.

OSC messages do not arrive

  • Check the device incoming port.
  • Check the device name and OSC prefix.
  • Make sure the sender uses UDP.
  • Check firewall or router rules if sending from another machine.

Touches or encoder movement do not control the target

  • In Network mode, connect the device to an outgoing OSC target.
  • In BLE Bridge mode, connect a bridge and assign a slot.
  • Leave edit mode; devices ignore performance touches while edit mode is active.

BLE Bridge is not found

  • Turn Bluetooth on.
  • Grant Bluetooth permission.
  • Tap refresh in the BLE Bridge section.
  • Make sure the bridge is powered and advertising the expected service.

LEDs appear in the wrong place

  • Confirm the virtual Grid size matches the software sending LED messages.
  • Remember that Grid coordinates start at the top-left.
  • Use x as column and y as row.
  • For level messages, use values from 0 to 15.
  • For map messages, verify the expected 8x8 block offsets.

Persistence

gladshmr saves:

  • Device layout and canvas size
  • Device names
  • Incoming ports
  • Network targets
  • Arc layout and input mode
  • BLE slot assignments
  • Visual shader settings per device name

Renaming a device keeps its current connection and visual settings, and moves the saved settings to the new name.
